# Security policy

## Credentials and local data

- Do not commit real API keys, access tokens, passwords, private keys, `.env` files, cloud credential files, database dumps, vector databases, logs, or generated bytecode.
- Files ending in `.example` contain placeholders only. Copy them to an ignored local file and provide credentials outside Git.
- Values prefixed with `CHANGE_ME_`, plus local compatibility tokens such as `ollama` and `dummy`, are development-only placeholders. Never deploy them unchanged or expose their services to an untrusted network.
- Prefer workload identity, instance roles, service-account attachment, short-lived credentials, or a secret manager over long-lived access keys.

If a real credential is committed, revoke or rotate it first. Removing it in a later commit does not remove it from Git history; coordinate a history rewrite separately when required.

## Reporting

Do not open a public issue containing secrets or sensitive data. Contact the repository owner privately with the affected path, commit, and recommended rotation scope.
